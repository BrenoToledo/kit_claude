# Entrega 1 (o método funcionando): plano de implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Objetivo:** um plugin do Claude Code que conduz um projeto novo do pedido até o plano seguindo as nove regras, com bloqueio por hooks.

**Arquitetura:** o repositório é marketplace e plugin. Hooks são scripts Node.js sem dependências que leem JSON do stdin e decidem por código de saída. Skills são arquivos Markdown encadeados; o estado do projeto-alvo vive em `docs/projeto/`.

**Tecnologia:** Node.js 18+ (ESM, `node:test`), Markdown, JSON.

**Spec:** `docs/specs/2026-11-11-kit-design.md` (seções Metodologia, Componentes 1 a 3, Caminho rápido, Entrega 1).

## Restrições globais

- Scripts em `.mjs`, zero dependências, só módulos `node:`. Funcionam em Windows, macOS e Linux.
- Hook nunca usa rede nem modelo e termina em menos de 200 ms.
- Erro interno de hook (stdin vazio, JSON inválido, arquivo ilegível) libera: código de saída 0. Um hook quebrado não pode travar o trabalho.
- Bloqueio: código de saída 2 e mensagem em português no stderr dizendo o motivo e a próxima ação.
- Todo texto para o usuário, nomes de arquivo e de skill em português.
- Cada `SKILL.md`: frontmatter com `name` e `description`; a descrição começa com "Use quando" e diz só quando usar; corpo com menos de 500 palavras; referências longas em arquivo separado.
- Cada skill da cadeia termina com a linha `Próxima etapa: <skill>, em conversa nova, lendo <arquivo>.`
- `modelos/CLAUDE.md` com menos de 100 linhas.
- Nome do plugin: `kit`. Nome do marketplace: `kit-claude`.
- Rodar os testes: `node --test tests/`.

## Foco da revisão

1. Caminho do Windows com barra invertida e espaços na entrada do hook: classificado igual ao caminho com barra normal.
2. Stdin vazio ou JSON inválido: hook sai com 0, sem exceção no stderr.
3. Sessão aberta em subpasta do projeto: a raiz é encontrada subindo diretórios.
4. `ESTADO.md` com fim de linha CRLF e espaços extras: campos lidos corretamente.
5. `.env.example` e valores de exemplo não bloqueiam; segredo dentro do `new_string` de um Edit bloqueia.

Cada item tem teste na tarefa dona do código (2, 3 e 4).

### Tarefa 2: biblioteca de projeto

**Arquivos:** criar `plugins/kit/hooks/lib/projeto.mjs`, `tests/projeto.test.mjs`, `tests/apoio.mjs`.

**Interfaces (produz):**
- `lerEntrada(): Promise<object|null>` lê todo o stdin e faz `JSON.parse`; devolve `null` se vazio ou inválido.
- `acharRaiz(cwd: string): string|null` sobe a partir de `cwd` e devolve o primeiro diretório que contém `.claude/kit-estado.json`; se nenhum, o primeiro que contém `.git`; se nenhum, `null`.
- `projetoAtivo(raiz: string): boolean` verdadeiro se `.claude/kit-estado.json` existe, é JSON válido e tem `ativo === true`.
- `lerEstado(raiz: string): {fase?: string, requisitos?: string, simulado?: string, proxima?: string}` lê `docs/projeto/ESTADO.md`; pega linhas `chave: valor` entre o primeiro par de `---`; tolera CRLF e espaços; chaves em minúsculas; arquivo ausente devolve `{}`.
- `modoRapido(raiz: string, agora?: Date): boolean` verdadeiro se `.claude/kit-rapido` existe, contém uma data ISO válida e ela é posterior a `agora` (padrão: hora atual).
- `ligarRapido(raiz: string, horas?: number): string` grava em `.claude/kit-rapido` a data ISO de agora mais `horas` (padrão 4) e a devolve. `desligarRapido(raiz: string): void` grava a data `1970-01-01T00:00:00.000Z` (não apaga arquivo).
- `classificar(caminho: string, raiz: string): "codigo"|"interface"|"livre"` normaliza `\` para `/` e compara em minúsculas:
  - `livre`: caminho relativo começando por `docs/`, `.claude/` ou `.github/`; ou extensão em `.md .txt .json .yaml .yml .toml .ini .cfg .lock .gitignore .csv`.
  - `interface`: extensão em `.html .htm .css .scss .sass .less .jsx .tsx .vue .svelte`; ou caminho contendo `/templates/` ou `/static/`.
  - `codigo`: qualquer outro.
- `tests/apoio.mjs` produz `criarProjeto(opcoes): string` (pasta temporária; opções `ativo`, `estado` como texto de `ESTADO.md`, `requisitos: boolean`, `rapidoAte: string` em ISO) e `rodarHook(arquivo: string, entrada: object|string): {codigo: number, stdout: string, stderr: string}` via `spawnSync("node", [...])` passando a entrada no stdin.

### Tarefa 3: bloqueio de código sem requisito e de interface sem simulado

**Arquivos:** criar `plugins/kit/hooks/bloqueio-codigo.mjs`, `tests/bloqueio-codigo.test.mjs`.

**Interfaces:**
- Consome: tudo de `lib/projeto.mjs`. Entrada do hook: `{session_id, cwd, tool_name, tool_input: {file_path | notebook_path}}`.
- Regra, nesta ordem; a primeira que casar decide:
  1. entrada `null`, sem caminho, raiz `null` ou projeto inativo → 0
  2. `modoRapido` → 0
  3. `classificar` devolve `livre` → 0
  4. `docs/projeto/REQUISITOS.md` não existe ou `estado.requisitos !== "aprovado"` → 2, stderr: `Bloqueado pelo kit: não há requisitos aprovados. Rode /kit:levantando-requisitos ou, para um ajuste pequeno, /kit:rapido.`
  5. `interface` e `estado.simulado` diferente de `aprovado` e de `nao-se-aplica` → 2, stderr: `Bloqueado pelo kit: tela sem simulado aprovado. Rode /kit:desenhando-solucao.`
  6. caso contrário → 0

## O que este plano não cobre

Execução com teste primeiro, verificação de segurança, revisão, handoff, pacotes de domínio, biblioteca de componentes, orquestração do Antigravity e privacidade: Entrega 2. O hook de "fim de tarefa sem teste" da spec também fica para a Entrega 2, junto com a skill `executando`.

## Limites conhecidos

- A instalação pelo `/plugin` e o disparo real dos hooks só podem ser validados no Claude Code da máquina do Breno. Os testes deste plano exercitam os scripts com entrada simulada.
- O formato de `installed_plugins.json` não é garantido; por isso o diagnóstico trata o arquivo como opcional.
